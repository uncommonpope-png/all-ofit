## Phase 5: Open-Source Grafts — COMPLETE

### 5a: Agent-Skills Spec Gate (`planning_engine.js`)

The shadcn/ui "source-first, copy-paste, verifiable" principle was applied as a **spec gate** to GSK's PlanningEngine.

**Spec Gate Architecture:**
```
Goal → _validateGoal() → Plan Steps → _validateSpec() → _validateStep() per step
                                              ↓
                            specStatus: 'passed' | 'rejected'
                            specValidation: { passed, stepValidations, hasCycle }
                                              ↓
                             _reviewPlan() (5-axis quality gate)
```

**Why this matters:** The root issue was that GSK generated 200+ variants of abstract meta-goals like "manifest a self-evolving, trans-dimensional Heavens 2.0 layer." These goals had NO concrete implementation, NO verification, and NO review gate. The spec gate ensures every step has:
- A concrete `tool` (not null, not invented)
- A `description` with verb+object (not just "manifest" or "evolve")
- `acceptanceCriteria` that can be checked post-execution

**Methods added:**
- `_validateStep(step)` — per-step check: tool present, description ≥8 chars, acceptance criteria present, description isn't verb-only
- `_validateSpec(plan)` — whole-plan check: all steps valid, dependency graph acyclic (DFS cycle detection)
- Integrated into `createPlan()` — runs after steps are created, tags plan with `specStatus`

### 5b: mem0/letta Memory Patterns (`mega_memory.js`)

Two open-source memory patterns grafted onto GSK's existing causal ledger:

**mem0 Pattern — Context-Aware Recall**
- `recall(context, limit, minScore)` — keyword-overlap scoring against context string, weighted by memory weight
- Works fully offline (no embedding vectors needed)
- Returns scored results with `_relevance` field

**letta Pattern — Versioned Memory**
- `upsert(key, entry)` — creates new version that supersedes the previous entry with the same key
- Preserves causal chain: `newEntry.supersedes = oldId`, `oldEntry.superseded_by = newId`
- `query()` defaults to filtering superseded entries (`includeSuperseded` opt-in)
- `search()` also filters superseded entries

**Memory type accessors** (letta-style compartmentalization):
- `getArchival()` — stable facts that persist across sessions
- `getLongTerm()` — episodic/experiential memories
- `getContextual()` — task-specific working memories

### 5c: Vera-AI Verification Gate (`planning_engine.js`)

Post-execution verification inspired by Vera-AI's automated code verification:

**`_verifyAcceptanceCriteria(step)`** — Runs after each step completes (both executor and internal paths). Heuristic-based:
- If criteria mentions "returned"/"exist"/"identified" → checks result is non-empty, no error
- If criteria mentions "completed"/"executed" → checks step.status === 'completed', no error in result
- If criteria mentions "null"/"absent"/"confirmed" → checks no error in result
- Default → result non-empty

**`_reviewPlan(plan, outcome)`** — 5-axis quality gate after plan execution:
1. **Correctness** — % of steps completed
2. **Security** — no unverified high/critical risk steps
3. **Maintability** — % of steps with acceptance criteria
4. **Verification** — % of steps that passed acceptance criteria
5. **Spec** — plan passed the spec gate

Aggregate score → `approved` (≥0.8) | `needs_review` (≥0.5) | `rejected` (<0.5)

**Integration:**
- Called after each step in `executePlan()`'s `executeStep()` (both executor and internal paths)
- `_reviewPlan()` called at end of `executePlan()` before `reflectOnPlan()`
