## Phase 1: Separation Steering + Collision Avoidance ✅

Rewrote `groundUnitTick()` with a steering pipeline.

**`_computeSteering(unit, dt)`**
- **Separation**: push away from neighbors within `SEPARATION_DIST` (3.0u). Force = `SEPARATION_FORCE * (1 - dist/SEPARATION_DIST)`, decays linearly.
- **Cohesion**: pull toward centroid of allies within `COHESION_DIST` (8.0u). Constant force = 0.5.
- Both clamped to `MAX_FORCE` (12.0).

**`_applySteering(unit, steering, dt)`**
- Accumulates velocity: `vel += steering * dt * 3`
- Clamped to `speed * MAX_SPEED` (max 3x base speed)
- Friction: `vel *= 0.95` per frame
- Face movement direction (lookAt along velocity)

**Seek/Arrive logic**: if distance > 0.5 → seek at `speed * 4`, else if > 0.01 → arrive at `speed * 2 * (dist/0.5)`

Result: units spread naturally, move in formation-like groups, slow down as they approach target.

## Phase 3: Grid-based A* Pathfinding ✅

No dependency — built from scratch since project uses vanilla JS with importmap (no npm).

**Grid setup** (`_initPathGrid()`)
- Cell size = 5u, coverage = ±6000u (2400 × 2400 cells)
- Blocks 20×20 cell area around each world coordinate (100u diameter blocked zones)

**`_findPath(fromPos, toPos)`**
- 4-directional A* with Manhattan heuristic
- Open set via `Set` iteration (lowest fScore selection per loop — O(n) but fine for <1000 cell searches)
- Reconstructs path as `Vector3[]` waypoints at cell centers
- Returns null if no path exists

**Integration**: `_activateCommand()` generates path on MOVE/ATTACK_MOVE for `isGroundUnit`. `cmd_move` state advances through waypoints with 1.5u arrival threshold.

## Phase 4: Behavior Tree Refactor ✅

Replaced the flat FSM with a composable Behavior Tree framework (~120 lines).

**BT Nodes:**
- `BTSequence(children)` — runs children in order, returns first non-SUCCESS
- `BTSelector(children)` — runs children in order, returns first non-FAILURE
- `BTCondition(pred)` — returns SUCCESS if predicate true
- `BTAction(fn)` — calls fn, returns SUCCESS
- `BTRunningAction(fn)` — returns RUNNING while fn returns false

**Tree Structure:**
```
Sequence [
  Selector [cmdAttack, cmdMove, cmdStop],
  Selector [chase, patrol]
]
```

First selector checks player commands (priority order: attack → move → stop). If no command, falls through to auto behavior (chase → patrol).

**Design notes:**
- `cmdMoveNode` returns `RUNNING` while moving → prevents fallthrough to auto behavior
- `cmdStopNode` handles both `cmd_stop` and `cmd_hold`
- All nodes write to `ud._btDesiredDir` which steering pipeline consumes identically regardless of source
- BT tree is built once per unit (`_buildGroundBT()`) and cached in `ud._btRoot`

### Critical Rules Adopted from emalorenzo/three-agent-skills

1. **Memory Management (our SPA needs this):** Dispose geometries/materials/textures on remove. Recursive disposal for hierarchies. Object pooling for bullets/particles/explosions. Reuse geometries + materials.
2. **Render Loop:** Single RAF. Delta-time for frame-rate independent animation. No `new THREE.*` inside render loop. Cap pixel ratio at 2. Static objects: `matrixAutoUpdate = false`.
3. **Geometry:** BufferGeometry only. Merge static geometry. InstancedMesh for many identical objects. LOD for complex models.
4. **Production Checklist:** Verify no memory leaks, `renderer.info` < 200 draw calls, `devicePixelRatio` capped at 2, debug helpers removed, texture compression (KTX2/Basis), test on mobile GPU.
