### Phase 5 — Spiral Galaxy ✅ (commit `402f945`)

Built above Grand Tower at y=500. 15K particles, 1 draw call.

**Technique (studied from 3 real demos):**
- Power-curve radius: `Math.random() ** 1.6 * 120` — clusters density near core
- 4 arms via `(i % 4) / 4 * PI * 2` + `radius * 1.5` spin
- Randomness scaled by `(1 - r/radius)` — scatter shrinks at edges
- Color: warm orange (0xffaa44) core lerp to cool blue (0x4488ff) edge
- Differential rotation: each particle speed = `1 / (0.3 + r * 0.02)`, inner spins faster
- Positions recomputed every frame via stored radii + angles
- Core orb: pulsing SphereGeometry at center

**References studied:**

## Deep NPC Study — Worker / Creep / Villager AI (40+ Notes)

Studied all three engines' NPC AI in depth: SC2 worker gather/return/build/repair loop + auto-acquire targeting, WC3 creep camp behavior (sleep/aggro/leash/smart AI levels), AoE2 villager task state machine + auto-farm + villager priority.

Full write-up appended to `LOST-MECHANICS-BIBLE.md` (NPC Mechanics section).

### Critical Findings

**SC2 Workers:**
- Default Acquire Level = DEFENSIVE → do NOT auto-acquire targets, NOT classified as threats by enemy AI
- ATP override = 10 for workers (vs AI players) — intentional balance favor
- SCV inherits threat level of whatever it repairs (if auto-repair on)
- Full repair = 25% of unit build cost. More SCVs = faster (time inversely proportional). Only 1 builds.
- Workers auto-idle on resource depletion — must manually reassign (no auto-transition)

**SC2 Auto-Acquire (4-Tier Priority):**
1. Threats (can shoot back + flagged special units: HT, Oracle, Disruptor, etc.)
2. ATP value (units=20, buildings=11, static defense=20)
3. Weapon preference (primary=anti-air for multi-weapon units)
4. Closest target (or closest angle for slow-turners like Thor)

**WC3 Creeps:**
- Camp = ONE unit. All attack together. Cannot pull apart.
- Sleep at night (aggro=0). Wake on attack/building/neutral building use.
- Leash: 400u from camp → 5s timer → return. Cannot re-aggro until fully returned.
- Level 6+: Hero magic resist. Level 7+: Smart AI (prioritize injured, heroes, buildings under construction). Chaos damage. Run from towers <60% HP.

**AoE2 Villagers:**
- Task state machine — 11+ task states with icon changes
- Auto-farm: when food sources exhausted, auto-build farms near TC/Mill. If no wood → auto-switch to wood.
- Villager Priority (Xbox): ratio system, 7 presets, manual mode
- AI opponents: hardcoded villager caps (38 Moderate / 78 Hard / 130+ Extreme)
- AI follows scripted build orders, deletes villagers for military space at pop cap

## Deep CPU AI Study — SC2 / WC3 / AoE2 Opponent Architecture

### SC2 AI Architecture (SC2Mapster Triggers + AI Module)

**5 Module Architecture (modular SC2 AI paper):**
| Module | Responsibility | Implementation |
|---|---|---|
| Worker Management | Gather resources at max efficiency | Scripted (2 per mineral, 3 per gas) |
| Build Order | Choose what to produce next | RL policy or scripted build |
| Tactics | Where to send army (attack/retreat) | Scripted or neural net |
| Micromanagement | Unit micro in combat | Scripted (focus fire, ability use) |
| Scouting | Track opponent info | Scripted + prediction |

**AI Vocabulary (SC2Mapster):**
- **Attack Wave**: Formalized unit group with target, timing, composition. Created via AI Module or Triggers.
- **Bully**: Harassment units sent to enemy base repeatedly (e.g. Reapers). Counted in Stock, excluded from attack waves by default.
- **Town**: AI's base location. Must have room for buildings.
- **Stock**: Unit count tracking. AI knows how many of each unit it has.
- **Personality**: Behavior profile affecting timing, aggression, composition.
- **Difficulty**: Per-function parameters (amount_easy/normal/hard). Scales unit counts, timing, response speed.
- **Wave Info**: Unit types, suicide/normal flag, staging point, target player/point/region.
- **Build Order**: `SetBuildUnitEx(amount_easy, amount_normal, amount_hard, unitId)` — sequential priority queue.
- **Defenders**: `Defenders(amount_easy, amount_normal, amount_hard, unitId)` — base defense units.
- **Attack Waves**: `SuicideOnPlayerEx(duration_easy, duration_normal, duration_hard, targetPlayer)` — sends wave as suicide (no return).
- **Wave Target**: Can be player, point, unit, region. Supports escorts.
- **Simple Trigger-based AI**: `UnitCreate()` + `UnitGroupAdd()` + `UnitGroupIssueOrder()` — no AI module needed.

**Key Insight**: SC2's AI system is a **scripted build order queue + attack wave scheduler**. No neural net needed for functional AI. Build order = what to build when. Attack wave = when to send what where. Difficulty scales parameters, not logic.

### WC3 AI Scripting (AI Editor + JASS)

**AI Editor Flow:**
1. Set race + units/buildings/heroes from tech tree
2. Build Priority: sequential list of buildings + workers to construct
3. Defenders: units that guard base
4. Attack Groups: unit compositions sent as waves
5. Upgrades: research priorities
6. Conditions: per-unit build conditions (e.g. "build workshop only after keep")

### RTS Unit Production (Barracks + Training System)

**Production Queue Architecture:**
1. `UnitProducer` component on building
2. Queue: units sit in ordered list with per-unit train timers
3. Training: timer counts down, resources deducted upfront
4. Spawn: unit appears at output point (rally point)
5. Rally point: newly spawned units auto-move to designated position
6. Attack-move rally: units stop to fight enemies en route
7. Multiple buildings: hotkey cycles through producers of same type

**Production Buildings (Cross-Engine):**
- SC2: Barracks (marine/marauder/reaper), Factory (hellion/tank/thor), Starport (viking/medivac/banshee)
- WC3: Barracks (footman/rifleman/knight), Arcane Sanctum (sorceress/priest), Workshop (mortar team)
- AoE2: Barracks (infantry), Archery Range (archers), Stable (cavalry), Siege Workshop (siege)
- Each building type produces a specific class of unit
- Some units require upgrades/tech buildings first (tech tree)
- Production can be queued: 5 marines at once, each trains sequentially

### City/Base Capture Mechanics (Cross-RTS)

**Common Patterns:**
1. **Adjacency**: must control adjacent territory to capture next node
2. **Occupation**: stand units in zone until capture timer completes
3. **War Declaration**: designate target, attack window (1 hour typical)
4. **Territory Chain**: expand via capturing connected nodes in sequence
5. **Ownership Limits**: max bases/cities per faction
6. **Defensive Phase**: invulnerability period after capture (balance mechanism)
7. **Resource Income**: held territories generate resources (fuel/munitions in CoH, territories in SC2)

**Implementation Patterns:**
- Capture point: sphere/zone with timer. Allied units speed it up, enemies contest.
- Base capture: destroy all enemy structures in zone, place own flag.
- Influence spread: gradual territory ownership based on proximity to owned structures.
- Adjacency graph: nodes connected by edges. Only can attack adjacent nodes.
